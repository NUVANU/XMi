# V0.1.2 workflow and acceptance scope

The supported delivery cycle is initial confirmation, current architecture generation, local validation, then advisory independent document review. Only unresolved/new material choices go back to the Owner. Their handling reply confirms the chosen action; there is no approval of a report, review startup or completion. Existing confirmed facts and unchanged ignore/defer dispositions are reused. Export authorization remains separate.

The standalone derived architecture is .xmi/context/architecture.md. Its 24 chapters also form the main text of TECHNICAL-SOLUTION-BLUEPRINT.md in the existing sixteen-file carrier. It is derived from confirmed facts and the approved blueprint, not a new source of product authority. Design examples, missing decisions and planned tests remain labelled.

Only actual native prompt delivery and exact displayed-list verification can authorize canonical confirmation. Tests use synthetic projects. Configured CODEX_HOME applies to both MCP and hook paths; logs outside its sessions directory cannot grant approval. A version or installation alone does not establish desktop loading or acceptance.

Release preparation includes the full test suite, static/build checks, byte-verified source/lite archives, fresh configured STDIO and an actual isolated desktop path. Cross-platform, clean-machine and external XUi/XDev acceptance are separate scopes. No remote publication or new independent-review service is included.
