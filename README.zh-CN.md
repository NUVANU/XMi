# XMi

**从“我有一个想法”，到“这就是我们确认要做的产品”。**

面向 AI 开发的产品澄清工具，让需求经过讨论、确认，再变成可追溯的 XSpec 规格。

[English](README.md) · **简体中文**

[快速开始](#快速开始) · [技术架构](docs/public/ARCHITECTURE.md) · [已知问题](docs/public/KNOWN-ISSUES.md) · [X Suite](https://github.com/NUVANU/X-Suite)

你不必先懂代码，才能说清楚想做的产品。但一句简短提示词，往往会让 AI 自己猜规则、补决定，甚至扩大范围。

**XMi 帮你在这些猜测变成代码之前，把产品讲清楚。**按模块讨论想法，看到哪些已经确认、哪些仍然待定，再导出开发者或其他 Agent 能够核对的版本化规格。

## XMi 能帮你做什么？

| 你手上的材料 | 逐步形成的结果 |
| --- | --- |
| 一个应用、工具、SaaS 或游戏的初步想法 | 带范围和验收标准的结构化产品模型 |
| 已有 Markdown、文本、DOCX 或 PDF 需求资料 | 有来源、等待审阅的提案，不会静默变成已采纳事实 |
| 含糊的术语、矛盾或缺失的规则 | 明确的定义、决策、冲突与待定问题 |
| 只有当前对话参与者看得懂的讨论 | 可持久保存的模型，以及供新会话阅读的项目上下文 |
| 看起来完整、却说不清谁批准的 PRD | 能核对确认条目、版本与来源的 XSpec |

适合正在定义首个产品的非技术用户、需要澄清模糊需求的开发者，以及需要把产品设计交给其他人或编码 Agent 的团队。

## 用一个小例子理解

你的起点可能只有一句话：

> “我想做一个让邻居预约共享工具的应用。”

开始开发前，XMi 帮你讨论：

- 同一件工具能不能被两个人预约重叠的时段？
- 借用人能否取消，最晚什么时候可以取消？
- 工具临时不可用时怎么办？
- 哪些规则属于首版，哪些明确暂时不做？

建议保持为提案，尚未决定的行为继续待定。对应决定被采纳前，你先审阅完整确认清单。

这是澄清过程示意，不代表 XMi 已经实现或验收了这个应用。

## 核心能力

### 按模块讨论，带着背景做决定

将当前规则、关联背景、待定问题与备选方案放在一起讨论。已确认、提案、拒绝和未解决条目分别保留，避免 AI 的一句建议悄悄变成产品需求。

### 让“确认”有实际含义

在文档所述 Codex 路径中，完整清单先展示在对话里，原生确认钩子核对真实用户回复，再由工具提交对应变更并回读存储状态。准备清单不等于完成确认。

### 让设计跨越单次对话

新建本地项目将权威模型保存在已确认项目根下的 `.xmi/xmi-state.sqlite`。`XMI-START-HERE.md` 和生成的上下文文件，为其他 Agent 提供当前设计、决定和待定事项的阅读入口。这些是派生视图：编辑文件不会批准产品决定。

旧共享数据库项目保留兼容，不自动迁移。接续现有项目时，沿用原项目 ID 与数据配置。

### 导出可以核对的开发规格

XMi 编译并校验 **XSpec**，输出带规格、配套文档和完整性信息的版本化交接包。审计与就绪检查暴露缺口和阻塞；分数不能覆盖阻塞，导出规格也不等于授权开发。

当前 XDev 交接契约使用 16 文件包及 manifest/内容哈希，见 [交接说明](docs/public/XDEV-HANDOFF.md)。

## 快速开始

当前公开源码：**V0.1 社区版系列 · 包版本 `0.1.1` · Apache-2.0**。

准备 **Node.js 24.20.0** 与 **npm 11.19.0**，克隆仓库或下载源码后，在仓库根目录执行：

```sh
npm ci --omit=dev --ignore-scripts
npm run check
npm run configure -- --host codex --data-dir "C:/XSuite/xmi-data"
```

数据目录需要是 XMi 安装目录以外的本地绝对路径。配置工具返回 `plugin_directory`，按宿主支持的本地插件入口添加，审阅原生钩子，再新建连接。配置工具不会覆盖既有配置，也不会接管现有数据库。

**完整步骤：**[安装、钩子信任、恢复与升级](docs/public/INSTALL.md)。源码不捆绑 Node.js 和依赖，首次安装需要联网下载。自检使用临时合成数据，不代表真实宿主或真人确认验收。

连接后可以这样开始：

```text
启用 XMi，和我按模块讨论产品想法。
请展示当前决定、关联背景、待定问题和建议。
尚未决定的行为保持待定。采纳变更前，先在对话中展示完整确认清单。
```

另有 `--host workbuddy` 配置入口，但真实表单、Skill 行为和干净接收端安装需要另行验证，见 [平台状态](docs/public/PLATFORMS.md)。本公开发行不提供 ChatGPT 网页或手机端托管服务。

## 技术设计

| 层次 | 职责 |
| --- | --- |
| Skills + MCP | 引导对话，提供结构化项目操作 |
| 领域服务 + 校验后的 Schema | 维护权威产品模型及状态迁移 |
| 本地 SQLite | 以事务保存产品状态、事件与回执 |
| 确认适配器 | 将展示的清单绑定到对应的真实确认流程 |
| XSpec 编译器与校验器 | 输出版本化交接包，核对引用、覆盖和完整性 |

Codex 确认路径将“获得真实回复授权”与“领域提交”分开。已完成提交但后续回执步骤失败时，按原回执恢复，避免再写一批。项目上下文带版本和哈希信息，便于区分过期派生资料。

详见 [架构概览](docs/public/ARCHITECTURE.md)、[项目内存储](docs/adr/ADR-023-PROJECT-LOCAL-DESIGN-DATA.md) 与 [范围收敛决定](docs/adr/ADR-021-XSPEC-CORE-SCOPE-CONVERGENCE.md)。

## 与 X Suite 的关系

- **XMi：**澄清并保存产品意图，输出 XSpec。
- **XDev：**治理开发范围，核对实施、Review 与 QA 证据。
- **XMem：**保存和检索版本化工程历史。
- **宿主与模型：**编码、调用工具、管理 Agent 执行。

XMi 不依赖 XMem 才能使用，权威产品模型也不会只存进记忆摘要。联合本地流程见 [X Suite](https://github.com/NUVANU/X-Suite)。

## 当前状态、隐私与边界

公开平台记录包括一次真实 Codex 16 项清单确认与回读成功，不代表所有宿主异常或并发路径均已验收。新的公开配置工具仍待干净接收端验收；Linux/macOS 真实宿主及 WorkBuddy 完整流程不能由这次结果推断。

风险匹配是确定性的辅助检查，含糊或混合范围的文字仍可能需要澄清。独立内容审查、真实 XDev/XUi 消费端验收，与本地 Schema/契约检查分别成立，详见 [已知问题](docs/public/KNOWN-ISSUES.md) 和 [平台证据](docs/public/PLATFORMS.md)。

文档所述路径在本地保存产品数据，宿主或模型仍可能将对话、工具上下文传给其服务商。仅导入有权使用的资料，不要在公开 Issue 中上传私密项目或凭证，见 [安全说明](SECURITY.md)。
