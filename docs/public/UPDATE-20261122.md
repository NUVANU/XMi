## Changed behavior / 变化

- **Native checklist delivery.** Replacement rows retain complete new text once, with issue context and associations. A bounded Stop preflight compares the pending checklist with the host's delivered final text, requests one correction on mismatch, and reports failure if still wrong. It writes no approval or product state. UserPromptSubmit, the actual reply, version binding and commit remain authoritative.
- **Incremental context.** `xmi_project_resume` accepts `detail: "incremental"` and `since_version`; later pages require the returned version. `xmi_project_get` accepts unique `item_ids` with `expected_version` for complete source-backed items. Counts, remaining pages, missing baselines and version conflicts are explicit. Full reads remain available.
- **Short receipts.** Validation and same-call commit validation can return summaries with readiness, gate status and counts. Full diagnostic readback remains available. Neither the short view nor a hash establishes independent evidence or consent.
- **Eligible blueprint reuse.** The native list displays carry-forward of approved technical choices for eligible changes to requirements, acceptance criteria and integration rules. The revision and binding update commit together. Real technical changes retain the existing review path; unchanged facts do not need another confirmation.
- **Optional local prototype adapter.** With explicit local-host configuration (`XMI_DREAMKIDS_PROTOTYPE=1`), a separate preview supports first-version behavior, observable checks, grouped choices and top-to-bottom flow presentation. A trusted host binds real answers to an account/chat/project and exact snapshot. A host-supplied output directory enables immutable sixteen-file export only after actual selection, validation and verified publication. The default ordinary MCP catalog stays unchanged. Downstream implementation still needs its own authorization.

中文要点：减少重复展示与确认，先读变化、需要时回读完整原文；适用修订沿用已确认技术选择。完整清单、真实回复、版本校验和风险阻塞继续保留。原型入口是可选本地宿主集成，未发布托管 DreamKids 服务。

## Upgrade and compatibility / 升级兼容性

Back up existing data, retain project IDs and routing, and reconnect after changing the source entry. Review/trust the new Stop and existing UserPromptSubmit hooks through supported host controls. An open old process is not proof of updated loading.

The blueprint-binding event is additive, but readers predating it need updating or the pre-upgrade backup. Do not assume an older reader can replay newly written data. Historical exports remain immutable; the sixteen-file XSpec carrier stays in use. No dependency upgrade is included in this source sync.

升级前保留旧安装和数据库备份。新版读取器与旧库回退要分别验证，不覆盖运行中的 SQLite，不改写历史确认或导出。首次配置工具不会接管已有数据库。
