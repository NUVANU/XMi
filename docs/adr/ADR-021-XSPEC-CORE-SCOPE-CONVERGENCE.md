# ADR-021 — 收敛到采访与 XSpec 交付

Date: 2026-10-16
Status: Accepted — Owner explicitly approved “按你的建议收敛吧，不要继续扩大开发”.

## 决策

XMi 的核心交付是：通过模块采访准确表达用户意图、梳理逻辑、确认产品决定，生成并校验一套可交给开发使用的 XSpec。

默认用户流程：

1. 读取已有项目或用户提供的设计文档。
2. 按模块展示现状、待定问题、相关规则与效果、冲突和建议，允许用户一起回复多个问题。
3. 自动保存有来源的未确认草稿；模块完成后展示完整编号清单，通过真实用户回复确认。
4. 检查歧义、冲突、遗漏、验收覆盖、风险范围、引用、schema 与文件完整性。
5. 在明确说明未完成项后，取得对本次精确文件版本的导出授权并交付 XSpec。

技术方案建议仅服务于规格的可实现性。代码架构、实现任务和开发执行仍归 XDev。不得自动推进新平台、通用代理系统或审查服务建设。

## 独立审查退出默认路径

- 独立模型审查为可选、暂缓的后续能力。停止第二阶段接入，不配置供应商、协议、密钥、计费、外发、子会话或新存储。
- 第一阶段源码、测试和兼容处理保留，避免未经要求删除已完成工作。默认本地/通用启动不再列出两个独立审查原型工具。仅内部显式注入测试运行器时列出；既有名称的兼容调用仍返回真实 UNAVAILABLE。
- 不允许把独立服务不可用当成“无法生成或导出任何 XSpec”，也不反复要求用户配置它。
- 普通采访内容继续按模块确认。文件读取与精确包导出继续使用已有授权流程；不增加批准步骤。

## 文件可交付与正式保证的界限

本次不重写 XSpec 0.3、历史导出或 XDEV-DELIVERY-HANDOFF/1，也不新增并行就绪状态。已有正式 READY_FOR_XDEV / BUILD_READY / PRODUCT_SPEC_READY 的保证条件保留：未执行独立审查仍不能标为已执行。

ADR-008 已允许通过包内在校验的 NOT_READY 候选包在 Owner 授权后导出。此路径继续作为缺少正式保证时的交付路径。包内仍列出开放问题和未通过的正式保证门槛；有效包不等于所有产品决定已经完成，更不等于生产就绪。缺失验收覆盖、无效引用、未处理的模式风险等原有包内在错误仍阻止导出。

因此，“独立审查对生成/候选导出可选”不是“独立审查门槛被伪造为通过”。如果以后确需变更下游正式就绪合同，应单独评审兼容方案，不在本次范围中顺带升级格式。

## 变更与验证边界

更新默认工具目录、宿主工作指引、导出授权文案和产品文档。以真实 MCP 内存连接、合成数据测试无审查配置时的编译/校验/导出、拒绝导出及状态保持。保留既有风险、确认、schema、消费端和正式就绪回归。

不修改真实 private-test-project 项目、不部署云端、不发布 GitHub、不打包、不修改原生钩子或信任记录。不引入依赖、数据库迁移或新服务。
