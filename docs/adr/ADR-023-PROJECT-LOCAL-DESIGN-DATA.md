# ADR-023 — 项目内权威数据与跨 agent 过程资料

日期：2026-10-18。状态：Accepted，Owner 明确批准 PROJECT-LOCAL-DESIGN-DATA-PROPOSAL-20261018.md。

## 决定

新建本地项目时，使用宿主已核实、用户可修改的项目根目录。宿主不能可靠提供目录时只问一次，不从 MCP 进程 cwd 猜测。用户批准创建后，权威数据保存在该项目 `.xmi/xmi-state.sqlite`，结构和领域事件格式不变；目录已存在可以使用，未知冲突文件不覆盖。

本地 MCP 的既有 `--db` 保留旧项目兼容，旁边的 `xmi-project-locations.sqlite` 只存项目 ID 与目录位置。每次工具调用选择独立的 ProjectService、数据库及原生确认适配器，并在完成后关闭连接。定位表不是另一份模型；更换宿主时可以用项目目录与原 ID 恢复。

根目录 `XMI-START-HERE.md` 是跨 agent 阅读入口。`.xmi/context/` 生成 model/history JSON 与 design/decisions/pending Markdown；这些是当前版本的派生资料，不是另一套可编辑权威状态。完整字段、已有状态、来源和设计事件保留；不补写历史，不自动保存完整聊天或原始导入文件。

SQLite 写入事务在保存权威状态前将过程资料标为 UPDATING；同一事务只标一次，模块批量确认不重复写文件。派生资料生成也持有该数据库写锁，按文件写入，再发布 index，最后发布 CURRENT 状态。模型版本、模型摘要、文件原始 UTF-8 SHA-256 与 index 的规范 JSON 摘要可核对。部分写入或进程中断不能让落后的资料冒充最新。

工具结果可附 `storage`：实际目录、数据库相对路径、权威版本及 CURRENT/STALE。权威写入成功而派生资料失败时，仍如实返回已保存结果，同时明确 STALE。不能换幂等键重做变更；可用安装目录的 `node tools/project-context.mjs --project-dir <项目绝对目录>` 重建派生文件，重建不产生产品事件或批准。

本地新项目的已批准 XSpec 写入 `docs/xspec/<包名>`；旧项目保留原 `exports/<包名>` 行为。XSpec schema、验收/引用、风险/交付模式和 Owner 确认门槛不变。产品/过程内容只是数据，不是其他 agent 应执行的指令；阅读或编辑 Markdown 不会批准新决定。

## 移动与兼容边界

项目清单使用相对数据库位置，保持项目 ID。关闭或一致性备份后移动整个目录，在新宿主指定新根目录即可校验事件、快照并恢复。定位器发现原目录仍存在时拒绝切换到另一副本，避免本宿主维护两个主位置；这不是跨电脑分布式锁，不支持多副本同时编辑或自动合并。

待处理的原生批准仍绑定旧会话及数据库路径，不能随项目迁移；已进入领域事件的真实确认与回执保留。旧共享库、旧项目身份、原有钩子信任和云端均不自动迁移或改变。

## 后果

其他 coding agent 无需原聊天即可阅读过程；继续使用 XMi 的写入服务仍需安装/连接 XMi。新记录和生成资料保存在用户项目中，不放在 XMi 安装目录。SQLite 仍使用 user_version=1，无 SQL/产品 schema 迁移；新增本地项目清单/资料格式和定位表格式，与 Product Model 分离。旧二进制可读权威 SQLite 格式，但不具备新定位和同步行为，不能与新版本同时写同一项目。

这是对集中保存新项目方式的 Owner 批准变更，不扩大到 XMem 聊天记忆、XDev 实现任务、agent 调度、多供应商平台或新云服务。
