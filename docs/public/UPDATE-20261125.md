# XMi V0.1.4 — finalization and formal-review evidence

Public source update · 2026-11-25 · Apache-2.0

## Changes / 更新内容

- Native finalization combines outstanding Owner choices, eligible confirmed-record carry-forward and readiness reporting. Numbered document pages and genuine bound short replies reduce repeated navigation. Preparing a review is not committing it.
- Formal-review material retains full text through a lossless span dictionary and source anchors. Receipt validation checks the frozen project/version, required IDs and actual findings; incomplete or mismatched evidence stays unresolved.
- The supported Windows path includes a formal-review launcher, isolated worker and recovery for matching original receipts. Capability/configuration failures remain explicit; an advisory review is not formal assurance.
- PreCompact/PostCompact hooks retain project/version context. Configured XMem is optional checkpoint storage; XMi's authoritative product model remains local SQLite. Checkpoint existence does not prove automatic recovery or correct later adoption.
- Existing native prototype, complete checklist delivery, incremental reads, project-local storage and sixteen-file handoff remain. Public packaging retains prior parser provenance and portable architecture-file checks, and includes the new Windows worker sources.

## Installation and configuration / 安装与配置

Use [main source ZIP](https://github.com/NUVANU/XMi/archive/refs/heads/main.zip) or a checkout, install dependencies with the pinned Node/npm versions and follow [INSTALL.md](INSTALL.md). Main is a moving source archive: record its commit. The fixed [v0.1.3 Release](https://github.com/NUVANU/XMi/releases/tag/v0.1.3) predates this update; its source/lightweight attachments remain unchanged.

Review and trust the configured UserPromptSubmit, Stop, PreCompact and PostCompact hooks, reconnect, then verify the active version and original data route. Installation, hook capability and successful real-host use are separate checks. Back up data before upgrading; older readers may need the pre-upgrade backup, as described in the [previous compatibility note](UPDATE-20261122.md).

### Optional Windows formal review

The automatic launcher checks Windows support, the project's applicable formal-review policy and trusted local plugin configuration. That configuration must supply `XMI_FORMAL_REVIEW_INSTALLED_DB` and `XMI_FORMAL_REVIEW_CODEX` with valid database/executable paths. Ordinary configuration does not prove this optional route is enabled. Do not copy machine-specific paths or credentials from another installation. See [the launcher source](../../tools/windows-formal-review.mjs) for its supported arguments and capability checks.

正式评审可能把所选规格材料交给配置的 Codex 模型服务并消耗额度，须具备相应项目与数据授权。安装插件不等于授权提交私有项目。缺少工具、配置、有效回执或仍有发现项时，如实报告阻塞；不能用安装成功、材料已生成或结构测试通过替代正式就绪结论。

## Validation and limits / 验证与边界

The public test set uses synthetic fixtures. Optional private-project replay cases and all real databases, conversations, machine configuration and internal evidence are excluded. Public packaging runs lint, TypeScript build, the public suite, a temporary-data self-check, parser-provenance verification and archive-closure checks. Completed counts are recorded in the README.

Source and protocol tests do not establish clean-machine Windows isolation, all host permissions, automatic post-compaction adoption, semantic completeness of arbitrary requirements, or end-to-end three-component acceptance. Required findings and NOT_READY states are retained. Existing [known issues](KNOWN-ISSUES.md), [platform scope](PLATFORMS.md), and third-party dependency audit findings remain applicable; this update does not upgrade dependencies or claim a clean security audit.
