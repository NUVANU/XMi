# Alpha known issues

ADR-019 removes the raw JSON fallback and extends native chat review to mode/risk operations. Generic desktop forms use lossless bounded pages; cloud retains authenticated page review. An already-open old dialog or loaded old MCP process requires cancellation/reload. Actual desktop Owner confirmation is an acceptance check, not a result established by isolated tests. Historical ZIPs predate this correction; this public source contains it.

Risk matching is deterministic review assistance, not a general semantic proof. Operational health pages and breaking-change classification no longer trigger the corresponding medical/deletion categories in the tested contexts; real medical/deletion behavior in mixed text remains reviewable. Metadata tags alone do not establish behavior. Matches include unresolved and future claims until an explicit disposition is reviewed.

DEFER_OR_EXCLUDE still exports EXCLUDE_SCOPE for complete item IDs. Mixed items identified by exclusion_requires_split_ids cannot be bulk-excluded; split current and deferred capabilities and review the replacement and old-item disposition. Ambiguous prose can still require clarification. Legacy risk dispositions need fresh review because their old projection did not retain the exact Owner rationale. They remain readable and auditable; new versioned resolutions preserve it, and stale/mixed/legacy dispositions block solution approval or valid export. Prior approvals are never promoted to new approval. Independent review and actual companion-consumer checks remain authoritative.

The former three moderate DOCX CLI-chain audit entries are removed by the maintained API-only source derivative. Root and isolated clean-install audits report zero; original upstream/source and browser component inventories still require advisory tracking. Bounded child controls remain. See SECURITY.md and DOCX-DEPENDENCY.md; upstream itself is not claimed patched. The separate private cloud source now installs cleanly and has zero production audit entries, but its development tools retain the unpatched braces advisory and are excluded from runtime assets. Its full audit is not clean and no hosted rollout is established by those local checks. It is outside this public distribution.

WorkBuddy form elicitation and clean-host installation of the new helper are unverified. Codex has one genuine 16-item module success path; isolated failure/concurrency tests do not prove all host-level conditions. Source and light ZIPs are Alpha review candidates, not a claim that every public plugin/platform acceptance gate is complete.
