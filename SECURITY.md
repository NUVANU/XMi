# Security and privacy

XMi Alpha stores canonical product data in the local directory selected by the user. Imported originals remain user-managed; extracted items, source locations and file digest are retained. Chat and file content may also be processed by the host/model under its settings.

Do not commit databases, credentials, private projects/transcripts, hook trust records or generated machine configuration. XMi does not require an author's API key or personal database connection.

Use GitHub private vulnerability reporting if enabled on this repository. If no private channel is enabled, open a minimal issue asking for a private contact; do not post exploit details, credentials or affected private data. No security contact address is asserted here.

Alpha is not production-safety certification. Independent review/isolation and real external consumers have stated limits. Do not forge confirmation through actor/approved fields, edited sidecars or simulated hooks. Historical MATCH diagnostics are not current authority.

Release preparation on 2026-10-15 upgraded the 1.x MCP SDK to 1.32.1 and locked fast-uri 3.1.8 for published advisories GHSA-6qxp-vccf-f47h and GHSA-hrr3-gc8f-f4qj. XMi uses local server/STDIO paths rather than the affected OAuth client configuration; this is not a claim about all SDK usage.

On 2026-10-15 the unused CLI chain mammoth -> argparse -> sprintf-js (GHSA-hp3w-g68c-fv3c) was removed through the Owner-approved private API-only derivative @xmi/mammoth-api@1.12.3-xmi.1. Retained parser source and LICENSE match the fixed official Mammoth 1.12.3 archive; upstream is not claimed patched. The root lockfile and isolated clean-install audit report zero vulnerabilities. See docs/public/DOCX-DEPENDENCY.md, UPSTREAM.json and the browser component inventory for provenance. Future upstream/parser advisories must still be reviewed against original identities; renaming a local package does not waive vulnerabilities.

Local DOCX extraction now runs only Mammoth's raw-text API in a fixed child entry, receiving bounded bytes over stdin rather than a filename or CLI arguments. The parent enforces 10 seconds, 1 MiB output and a 128 MiB V8 old-heap setting; this heap setting is not an operating-system limit on total process memory. Only Windows runtime environment essentials are inherited. Parser failure returns a static error, without private content or third-party diagnostics, and cannot write canonical state. The child is a resource boundary, not a claim of an OS security sandbox. Tests block loading argparse/sprintf-js during actual extraction and retain precision-like document text as data.

The separate private cloud source uses the same reproducibly rebuilt browser API, with a 5 MiB input and 1 MiB text limit. Current lockfile dependencies are bundled with explicit component/version/input/license records instead of the older upstream prebuilt dependency copies. Hosting resource boundaries still apply; no local subprocess is available remotely. On 2026-10-15 the cloud peer conflict was removed and patched framework, SDK and parser/tool dependencies were locked and verified with an ordinary clean install. Its production dependency audit is zero. Its full development tree still has eight high-severity entries from the single unpatched braces advisory GHSA-vfj7-8cjw-p6xm, through build/lint tools. Only trusted repository source is built; imported design documents are never glob patterns. A post-build source-map check rejects that chain in deployable assets (83 maps, 572 source entries checked). This boundary does not patch braces or make the full audit clean: build/lint must remain in a disposable environment without production credentials and must not process untrusted patterns. This private service and its configuration are outside the public source distribution. Local cloud checks do not prove a hosted update; cloud publication remains a separate Owner review. No Mammoth CLI is included or supported in XMi.
